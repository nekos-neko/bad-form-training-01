🔵 セッション作成フロー（研修開始時）

  1. 講師が admin/index.html を開く
  2. 自動で Worker に POST /session/new を送信
  3. WorkerがGitHub APIから original.html を取得
  4. KV にセッションID・HTMLを保存
  5. 管理画面にセッションID・参加者URLが表示される
  6. 講師が参加者に view.html?s=xxxx のURLを共有

🟢 改善反映フロー（ディスカッション後）

  1. 講師が改善点をテキストで入力・送信
  2. Worker が KV から現在のHTMLを取得
  3. 改善点＋HTMLを Claude API に送信
  4. Claudeが改善済みHTMLを返す（30秒〜1分）
  5. 改善済みHTMLを KV に上書き保存
  6. 参加者が view.html を更新すると改善後が表示される

🔴 参加者の閲覧フロー

  1. URLの ?s=xxxx からセッションIDを取得
  2. Worker に GET /session/{id} を送信
  3. WorkerがKVからHTMLを返す
  4. Blob URLを生成しiframeに表示
  5. 🔄更新ボタンで最新の改善版を取得できる

🟠 開発・デプロイフロー

  1. ローカルでHTMLファイルを編集
  2. git push で GitHub に反映
  3. GitHub Pagesが自動でファイルを公開（1〜2分）
  4. worker.js はCloudflareダッシュボードで編集・デプロイ
  5. シークレット（APIキー等）はCloudflare Settingsで管理

📄 ソースファイル一覧

ファイル ホスト場所 役割 主な利用者
original.html GitHub Pages BADパターンを含む研修用フォーム（元データ）。セッション作成時にWorkerがGitHub APIで読み込みKVに格納する システム（自動取得）
GoodExample.html GitHub Pages 全改善点を適用した「答え合わせ」用フォーム。研修終了後に参加者へURLを直接共有する 参加者
admin/index.html GitHub Pages 講師用管理画面。セッション作成・改善点入力・履歴確認・参加者URL共有を行う 講師
view.html GitHub Pages 参加者用の現状確認画面。URLパラメータのセッションIDでWorkerからHTMLを取得しiframe表示する 参加者
compare.html GitHub Pages ビフォー・アフター比較画面。左にoriginal.html、右にWorkerから取得した改善版を並べて表示する 参加者・講師
worker.js Cloudflare Workers APIエンドポイントを提供するサーバーレス関数。セッション管理・Claude API呼び出し・KV読み書きを担う システム（自動）
wrangler.toml ローカルPC（設定） Cloudflare Workersのデプロイ設定ファイル。KVバインディング名・ワーカー名などを定義する 開発者

🔑 シークレット・環境変数

ANTHROPIC_API_KEY
Claude API認証キー。Cloudflare WorkersのSecretsに設定
GITHUB_TOKEN
GitHub APIでoriginal.htmlを読み取るためのPAT。Cloudflare Secretsに設定
SESSION_STORE（KV）
Cloudflare KV Namespace。セッションごとのHTML・メタ・履歴を保存
